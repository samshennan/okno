Three related fixes to the error handling path in slideshow.html:

**Fix A: fetchWithRetry 404 short-circuit (BUGFIX-03 part 1)**

Modify `fetchWithRetry()` (around line 599) to NOT retry 4xx responses. Currently it retries all non-ok responses 7 times, which means a 404 (intentional "no photos today") takes 10+ seconds of retries before the fallback message appears.

Add this check BEFORE the existing `if (!response.ok)` line:
```javascript
// 4xx errors are intentional, not transient -- return immediately, let caller handle
if (response.status >= 400 && response.status < 500) {
  return response;
}
```

This returns the 404 response to the caller so it can show the fallback message instantly. Only 5xx and network errors should be retried.

**Fix B: On This Day message stays visible until fallback loads (BUGFIX-03 part 2)**

Find the "No photos from today" message display logic (around line 893 or in `showOnThisDayMessage()`). Currently it auto-hides after 5 seconds via `setTimeout`. REMOVE the auto-hide timeout entirely. Instead, hide the message inside `showSinglePhoto()` when the first fallback random photo successfully appears:
```javascript
// In showSinglePhoto(), hide the OTD message if visible
const otdMsg = document.getElementById('onThisDayMessage');
if (otdMsg) otdMsg.style.display = 'none';
```

This ensures no black screen gap between message disappearing and fallback photo appearing.

**Fix C: 502 proactive baseUrl refresh (BUGFIX-05 frontend)**

In `createPhotoElement()` (around line 726-740), when a 502 response is detected from the backend, fire a proactive POST to `/api/health/refresh` to trigger backend baseUrl refresh. The slideshow should continue showing the previous photo (existing behavior -- function returns null) while the refresh happens in the background:
```javascript
if (response.status === 502) {
  console.warn('502 from backend, triggering baseUrl refresh');
  fetch('/api/health/refresh', { method: 'POST' }).catch(() => {});
  return null; // Keep showing previous photo
}
```

Do NOT block on the refresh -- fire and forget. The next slideshow cycle will benefit from refreshed URLs.

Important: Check whether `/api/health/refresh` endpoint exists in the backend. If it does not, use a different existing endpoint or skip the proactive refresh part and just ensure the 502 is handled gracefully (return null, keep previous photo, let fetchWithRetry handle the 5xx retry on next cycle). Do NOT create new backend routes in this plan.
