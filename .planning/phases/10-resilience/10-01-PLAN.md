In `photo-proxy.js`, modify the catch block (lines 143-149) to detect token errors and return 401 instead of 502.

Replace the current catch block:
```javascript
} catch (error) {
  logger.error('Failed to proxy photo:', { error: error.message, stack: error.stack });

    error: 'proxy_failed',

```

With:
```javascript
} catch (error) {
  logger.error('Failed to proxy photo:', { error: error.message, stack: error.stack });

  // Detect token errors (revoked/expired refresh token) and return 401
  // so the frontend shows the reconnect overlay instead of retrying silently.
  // Primary check: google-auth-library sets response.status on HTTP errors
  // Fallback: string match on common Google OAuth error messages
  const isTokenError = error.response?.status === 401
    || error.message?.includes('invalid_grant')
    || error.message?.includes('Token has been expired or revoked');

  if (isTokenError) {
    return res.status(401).json({
      error: 'authentication_required',
      message: 'Google token expired or revoked. Please re-authenticate.'
    });
  }

  res.status(502).json({
    error: 'proxy_failed',
    message: error.message
  });
}
```

This change means:
- Token errors (revoked refresh token, expired with no refresh) return 401 with `authentication_required`
- The frontend's existing 401 handler (slideshow.html line 1237) catches this and shows the reconnect overlay
- The existing 502+authentication_required detection in fetchWithRetry (line 1046-1055) becomes a redundant safety net -- keep it, it's harmless
- Non-token errors (network issues, Google outages) still return 502 and trigger normal retry logic
- Other users are completely unaffected (per-user OAuth2Client, per-user cache, per-user sessions)
