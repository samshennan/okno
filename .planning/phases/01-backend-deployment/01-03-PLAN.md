<task type="auto">
  <name>Implement image proxy for random photo serving</name>
  <files>photo-proxy.js</files>
  <action>
Create photo-proxy.js implementing the image proxy from research Pattern "Image Proxy (Critical)":

1. Import express Router, oAuth2Client from auth.js, photoCache from photo-cache.js, winston logger
2. Create Express router
3. GET /api/photo/random route:
   - Call photoCache.getRandomItem()
   - If no item (empty cache), return 503 JSON:
     ```javascript
     {
       error: 'no_photos',
       message: 'No photos in cache. Use the picker to select photos first.'
     }
     ```
   - Get access token: `const { token } = await oAuth2Client.getAccessToken()`
   - Append size parameters to baseUrl (w2048-h1536 for iPad Pro landscape per research):
     ```javascript
     const imageUrl = `${item.baseUrl}=w2048-h1536`;
     ```
   - Fetch image bytes from Google with Authorization header:
     ```javascript
     const imageResponse = await fetch(imageUrl, {
       headers: { 'Authorization': `Bearer ${token}` }
     });
     ```
   - If fetch fails (!imageResponse.ok), log error and return 502 JSON:
     ```javascript
     { error: 'proxy_failed', message: `Google returned ${imageResponse.status}` }
     ```
   - Stream image to client:
     ```javascript
     res.set('Content-Type', imageResponse.headers.get('content-type'));
     res.set('Cache-Control', 'no-store');  // Don't cache proxied images
     res.set('X-Photo-Id', item.id);
     res.set('X-Photo-CreateTime', item.createTime || '');
     imageResponse.body.pipe(res);
     ```
   - Log "Served random photo {id}"
4. Wrap fetch in try/catch - on error, log and return 502 error
5. Export router

This is the CRITICAL architectural piece per research - Picker API baseUrls require auth headers. Browser <img> tags cannot add headers, so backend must proxy.

Use exact fetch/stream pattern from research "Random Photo Endpoint" example.
  </action>

  </verify>

2. Create Express router
3. GET /api/health route:
   - Get current credentials: `const tokens = oAuth2Client.credentials`
   - Return JSON with all diagnostic info per INFRA-04 requirement:
     ```javascript
     {
       status: 'ok',
       uptime: process.uptime(),
       timestamp: new Date().toISOString(),
       auth: {
         hasTokens: !!tokens.access_token,
         tokenExpiry: tokens.expiry_date
           ? new Date(tokens.expiry_date).toISOString()
           : null,
         hasRefreshToken: !!tokens.refresh_token,
         expiresIn: tokens.expiry_date
           ? Math.floor((tokens.expiry_date - Date.now()) / 1000)
           : null  // seconds until expiry
       },
       cache: {
         totalItems: photoCache.size(),
         sessionId: photoCache.getSessionId() || null,
         lastRefresh: photoCache.getLastRefresh() || null,
       },
       lastApiCall: photoCache.getLastApiCall() || null,
       memory: process.memoryUsage(),
     }
     ```
4. Export router

This provides the operational visibility requested in context: "token status, cache size/stats, last API call timestamp, errors, memory usage, uptime".
