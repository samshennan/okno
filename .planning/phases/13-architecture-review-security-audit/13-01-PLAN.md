<task type="auto">
  <name>Task 1: Fix session fixation in OAuth callback</name>
  <files>auth.js</files>
  <action>
In `auth.js`, in the `GET /auth/callback` handler, replace the section that sets `req.session.userId` (around line 217) with session regeneration. The current code:

```javascript
// Store userId in session
req.session.userId = userId;

logger.info('OAuth callback successful', { userId, email: userEmail });
res.redirect('/');
```

Must become:

```javascript
// Regenerate session to prevent session fixation attacks
req.session.regenerate((err) => {
  if (err) {
    logger.error('Session regeneration failed:', { error: err.message });
    return res.redirect('/login?error=session_error');
  }

  // Set userId on the NEW session
  req.session.userId = userId;

  // Save session before redirect to ensure it's persisted
  req.session.save((saveErr) => {
    if (saveErr) {
      logger.error('Session save failed:', { error: saveErr.message });
      return res.redirect('/login?error=session_error');
    }
    logger.info('OAuth callback successful', { userId, email: userEmail });
    res.redirect('/');
  });
});
```

**Key details:**
- The `oauthState` does NOT need to be preserved -- it was already validated above and is never needed again.
- The `getOAuth2ClientForUser(userId)` and `saveTokens(userId, tokens)` calls that happen BEFORE this point are fine -- they don't depend on the session.
- `req.session.save()` ensures the session is written to SQLite before the redirect, preventing race conditions where the redirect arrives before the session is stored.

**Step 1: Install express-rate-limit**

```bash
npm install express-rate-limit@^8.3.1
```

IMPORTANT: Use v8.3.1+ to avoid CVE-2026-30827 (IPv4-mapped IPv6 bypass).

**Step 2: Add rate limiting to server.js**

After the `const path = require('path');` / `const fs = require('fs');` block at the top of server.js (around line 22), add:

```javascript
const rateLimit = require('express-rate-limit');
```

After the `app.use(express.json());` line (around line 92), add the rate limiter definitions:

```javascript
// Rate limiting -- auth endpoints (10 req/15min per IP)
const authLimiter = rateLimit({
  windowMs: 15 * 60 * 1000,
  max: 10,
  standardHeaders: true,
  legacyHeaders: false,
  message: { error: 'too_many_requests', message: 'Too many attempts, please try again later' }
});

// Rate limiting -- feedback endpoint (5 req/15min per IP)
const feedbackLimiter = rateLimit({
  windowMs: 15 * 60 * 1000,
  max: 5,
  standardHeaders: true,
  legacyHeaders: false,
  message: { error: 'too_many_requests', message: 'Too many submissions, please try again later' }
});
```

Then apply the limiters to routes. Add `authLimiter` to the auth routes:
- Change `app.use('/auth', authRouter);` to add the limiter on login and callback specifically. Since the authRouter handles its own sub-routes, apply the limiter directly to the specific paths:

```javascript
app.use('/auth/login', authLimiter);
app.use('/auth/callback', authLimiter);
app.use('/auth', authRouter);
```

For feedback, the router is already mounted at `/api/feedback` with `requireAuth`. Add the feedbackLimiter before it:

```javascript
app.use('/api/feedback', requireAuth, feedbackLimiter, feedbackRouter);
```

Remove the existing `app.use('/api/feedback', requireAuth, feedbackRouter);` line and replace with the above.
