Append a `## Phase 14 Surface Validation` section to SECURITY-AUDIT-v3.md. This is the targeted regression check — each surface gets a verdict + the exact command(s) used + the result.

Run these checks and record results inline:

**1. CSP — no inline `<script>` or `<style>` in any HTML, no `'unsafe-inline'` in CSP headers.**

```bash
# Should return zero matches (excluding the closing tags inside head/body comments — manually inspect any hits)
grep -nE "<script[^>]*>[^<]" public/*.html
grep -nE "<style[^>]*>[^<]" public/*.html

# Should show script-src-attr 'none' and style-src-attr 'none', no 'unsafe-inline' in script-src or style-src
grep -nE "scriptSrc|styleSrc|script-src|style-src|unsafe-inline" server.js
```

Verdict criteria: PASS only if (a) zero inline script/style content in public/*.html, (b) `script-src-attr: ['none']` present, (c) `style-src-attr: ['none']` present, (d) `'unsafe-inline'` does NOT appear in `scriptSrc` or `styleSrc` arrays. Any deviation = FAIL with finding ID (e.g., F-N1).

**2. /auth/status DONATION_URL reflection.**

```bash
grep -nE "getDonationUrl|DONATION_URL|buy\.stripe\.com" auth.js
```

Verdict criteria: PASS only if the regex `^https://buy.stripe.com/` (or equivalent anchored prefix) gates the env var before reflection. If the value can flow to `/auth/status` without validation = FAIL.

**3. multer 2.1.x resolved.**

```bash
node -e "console.log(require('./package-lock.json').packages['node_modules/multer'].version)"
grep -nE "multer\(|multer\.|fileFilter|fileSize" feedback.js
```

Verdict criteria: PASS only if (a) resolved version is `2.1.x`, (b) the upload handler still has a `fileFilter` that checks BOTH MIME type AND file extension, (c) `limits.fileSize` is set. Any missing = FAIL.

**4. google-auth-library v10 resolved + breaking changes vs current usage.**

```bash
node -e "console.log(require('./package-lock.json').packages['node_modules/google-auth-library'].version)"
grep -nE "OAuth2Client|google\.auth|setCredentials|getAccessToken|refreshAccessToken" auth.js
```

Verdict criteria: PASS only if (a) resolved version is `10.x`, (b) `OAuth2Client` constructor signature in auth.js matches v10 expectations (3-arg form: clientId, clientSecret, redirectUri), (c) no usage of removed/deprecated APIs (e.g., `request()`, deprecated event names). Spot-check the v10 changelog for any breaking change that would silently affect the per-user OAuth2Client cache pattern.

**5. Feedback input limits.**

```bash
grep -nE "2000|254|fileFilter|email.*regex|@.*\\.|description|reason" feedback.js
```

Verdict criteria: PASS only if (a) description/reason capped at 2000 chars, (b) email capped at 254 chars, (c) email regex present and enforced (anchored, not just `includes('@')`), (d) `fileFilter` requires extension AND mimetype, (e) `type` field validated against an enum/allowlist. Any missing = FAIL.
