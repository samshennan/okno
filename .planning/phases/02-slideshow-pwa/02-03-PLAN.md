  <how-to-verify>
**Test Environment:**
- iPad Pro 1st Gen (or similar iOS device) running iOS 16.x
- Production deployment at okno.moonacle.com OR local network access to dev server
- Safari browser (required for Add to Home Screen)

**Test Procedure:**

1. **PWA Installation & Fullscreen Mode (DISP-01, PWA-02):**
   - Open Safari on iPad, navigate to slideshow URL
   - Tap Share button (square with arrow)
   - Select "Add to Home Screen"
   - Verify custom "OKNO" icon appears (not website screenshot)
   - Tap home screen icon to launch
   - **VERIFY:** No Safari address bar, no toolbars, no browser chrome visible
   - **VERIFY:** Black background, fullscreen photo display

2. **Smooth Crossfade Transitions (DISP-02, DISP-03):**
   - Set interval to 10 seconds (tap screen, select "10s" button)
   - Watch 5+ photo transitions
   - **VERIFY:** Photos crossfade smoothly (1-2 second opacity transition)
   - **VERIFY:** No white flash between photos
   - **VERIFY:** No loading spinner or delay (next photo preloaded)
   - **VERIFY:** Transitions feel seamless and high-quality

3. **Memory Leak Prevention - A/B Swap Pattern (DISP-06):**
   - Keep slideshow running for 30+ minutes (300+ transitions with 10s interval)
   - Open Safari DevTools (connect iPad to Mac via cable, use Safari > Develop menu)
   - Go to Memory tab, take heap snapshot after 30 minutes
   - **VERIFY:** Heap size stable (no continuous growth indicating leaks)
   - **VERIFY:** Only 2 <img> elements in DOM (A/B swap pattern working)
   - **VERIFY:** Old blob URLs properly revoked (check Memory tab for orphaned blobs)
   - Console shows no "memory pressure" warnings

4. **Backend Photo Randomization (DISP-05):**
   - Watch 10+ consecutive photo transitions
   - **VERIFY:** Each photo is different (backend serving random photos from cache)
   - Note photo filenames in Network tab (if visible) - should be varied
   - **VERIFY:** No repeating pattern or stuck on same photo

5. **Screen Wake Lock (PWA-01):**
   - Start slideshow from home screen icon
   - Check browser console for "Screen wake lock enabled via NoSleep.js" message
   - Do NOT touch iPad for 10 minutes
   - **VERIFY:** Screen stays at full brightness (no dimming)
   - Leave running for 2 hours untouched
   - **VERIFY:** Screen never dims or sleeps
   - **VERIFY:** Slideshow continues advancing every interval

6. **Network Resilience (INFRA-03):**
   - Start slideshow with normal network connection
   - Watch 2-3 photos load successfully
   - Turn off WiFi on iPad OR disconnect router briefly (30 seconds)
   - **VERIFY:** Slideshow continues showing current photo (no crash, no white screen)
   - Turn WiFi back on
   - Wait one interval
   - **VERIFY:** Slideshow automatically resumes fetching new photos
   - Check console for retry attempt messages

7. **iOS Guided Access Mode (PWA-03):**
   - Launch slideshow from home screen icon
   - Triple-click side button (or home button on older iPads)
   - Select "Guided Access" → Start
   - Try to swipe away, press home button, access control center
   - **VERIFY:** iPad locked to slideshow (can't exit without passcode)
   - **VERIFY:** Slideshow continues working normally
   - **VERIFY:** Tap screen shows/hides controls (if desired)
   - Triple-click side button → Enter passcode → End Guided Access to exit

8. **URL Parameter Interval (DISP-04):**
   - Exit slideshow, relaunch from Safari with URL: `/slideshow.html?interval=30`
   - **VERIFY:** Photos advance every 30 seconds (not default 10s)
   - Try `?interval=120` (2 minutes)
   - **VERIFY:** Photos advance every 2 minutes

9. **Service Worker Offline Caching:**
   - Open slideshow in Safari (not PWA)
   - Open DevTools (connect iPad to Mac, use Safari > Develop menu)
   - Go to Application tab > Service Workers
   - **VERIFY:** Service Worker shows "activated and running"
   - Refresh page, check Network tab
   - **VERIFY:** Some requests show "from ServiceWorker" in Size column

**Expected Results:**
- All 5 Phase 2 success criteria TRUE
- No console errors during any test
- Slideshow feels polished, reliable, and production-ready

**Common Issues & Troubleshooting:**
- If screen still dims: Check NoSleep enabled message in console, verify user interaction happened before enable() call
- If white flash between photos: Check Service Worker caching working, verify blob URLs used, check network speed
- If PWA doesn't go fullscreen: Verify manifest has `display: "fullscreen"`, check Apple meta tags present
- If Guided Access exits on tap: Disable touch in screen regions via Guided Access options
- If memory grows continuously: Check DOM has only 2 img elements, verify old blob URLs revoked via URL.revokeObjectURL()
- If same photo repeats: Check backend /api/photo/random returns different baseUrls, verify Phase 1 caching working
