Add retry logic to handle network errors gracefully. Insert before existing `createPhotoElement()` function (around line 468):

```javascript
// Exponential backoff retry for network resilience
async function fetchWithRetry(url, maxRetries = 7) {
  for (let attempt = 0; attempt <= maxRetries; attempt++) {
    try {
      const response = await fetch(url);
      if (!response.ok) throw new Error(`HTTP ${response.status}`);
      return response;
    } catch (error) {
      if (attempt === maxRetries) {
        console.error(`Fetch failed after ${maxRetries} retries:`, error);
        throw error; // Final attempt failed
      }

      // Exponential backoff: 10ms, 20ms, 40ms, 80ms, 160ms, 320ms, 640ms
      const baseDelay = Math.pow(2, attempt) * 10;
      const jitter = Math.random() * baseDelay * 0.1; // +/- 10% jitter to prevent thundering herd
      const delay = baseDelay + jitter;

      console.log(`Retry ${attempt + 1}/${maxRetries} after ${delay.toFixed(0)}ms`);
      await new Promise(resolve => setTimeout(resolve, delay));
    }
  }
}
```

WHY exponential backoff: Network errors often transient (weak WiFi signal, brief disconnect). Retrying with exponential delays (10ms → 640ms over 7 attempts) gives network time to recover without hammering server. Jitter prevents synchronized retries from multiple clients.

WHY blob URLs: Using blob URLs instead of direct img.src prevents browser cache issues with expired baseUrls. Each fetch is fresh, and blob cleanup happens automatically via GC.
