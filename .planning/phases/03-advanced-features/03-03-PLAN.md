<objective>
Portrait pair mode — detect portrait photos and display them side-by-side.

Purpose: When the slideshow encounters a portrait-orientation photo, it automatically fetches another portrait and displays both side-by-side in landscape, making efficient use of the iPad's landscape screen. This matches Aura's $200+ flagship feature.

Output: Working portrait pair mode that intelligently pairs portrait photos for side-by-side display.
</objective>

<context>
@.planning/PROJECT.md
@.planning/ROADMAP.md
@photo-cache.js
@photo-proxy.js
@public/slideshow.html
@config.js (from 03-01)

NOTE: slideshow.html already has portrait detection (`img.naturalHeight > img.naturalWidth`),
dual layout CSS (`.dual-left`, `.dual-right`), and a `pendingPortrait` variable.
The current implementation recursively calls loadPhoto() to find a second portrait, which
can cause UI stutters. This plan improves it with backend-assisted portrait filtering.
</context>

<tasks>

<task id="1" type="code" priority="must-have">
  <title>Add portrait filtering to photo-cache.js</title>
  <detail>
Add `getRandomPortraitItem()` to photo-cache.js:

1. Filter `cache.mediaItems` where the item's dimensions indicate portrait orientation
2. Picker API returns `width` and `height` fields on each mediaItem (confirmed in cache structure)
3. Portrait = `height > width` (from the mediaItem metadata, NOT from loading the image)
4. Return random portrait item, or `null` if no portraits in cache

Also add `getPortraitCount()` to return count of portrait photos in cache.

Export both new functions.
  </detail>
  <files>photo-cache.js</files>
</task>

<task id="2" type="code" priority="must-have" depends="1">
  <title>Add portrait query parameter to photo-proxy.js</title>
  <detail>
Modify `GET /api/photo/random` to accept `?portrait=true` query parameter:

1. If `portrait=true`, call `photoCache.getRandomPortraitItem()` instead of `getRandomItem()`
2. If no portraits available, fall back to `getRandomItem()` (don't error out)
3. Add `X-Photo-IsPortrait: true/false` response header based on item dimensions
4. This works alongside `?onThisDay=true` — both can be combined: `?onThisDay=true&portrait=true`
  </detail>
  <files>photo-proxy.js</files>
</task>

<task id="3" type="code" priority="must-have" depends="2">
  <title>Improve portrait pair logic in slideshow frontend</title>
  <detail>
Refactor the existing portrait pair logic in slideshow.html:

1. Read `portraitPairs` from `window.appConfig`
2. When portrait pairs enabled and a portrait photo is detected:
   - Instead of recursively calling loadPhoto(), fetch `/api/photo/random?portrait=true` for the second photo
   - This guarantees the second photo is portrait (no recursive guessing)
3. Display both portraits using existing `.dual-left` and `.dual-right` CSS layout
4. When portrait pairs disabled, show all photos full-width (existing behavior)
5. Clean up the `pendingPortrait` logic to use the new backend-assisted approach
  </detail>
