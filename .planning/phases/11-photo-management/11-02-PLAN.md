  <name>Task 1: Slideshow hide button, photo ID tracking, toast with undo</name>
  <files>public/slideshow.html</files>
  <action>
**Photo ID tracking:**
In the fetch response handler for `/api/photo/random`, read the `X-Photo-Id` header (already set by backend) and store it on the img element:
```javascript
const photoId = response.headers.get('X-Photo-Id');
img.dataset.photoId = photoId;
```
Do this for BOTH the primary and secondary img elements (the two stacked photos used for crossfade). This ensures the currently-visible photo always has a photoId in its dataset.

**Hide button:**
Add a hide button as a SEPARATE floating element (not inside #controls). Position it in the top-right corner. It should appear/disappear with the SAME tap-to-show-controls gesture that toggles #controls visibility.

HTML structure:
```html
<button id="hideBtn" class="hide-button" onclick="hideCurrentPhoto()" disabled>
  <i data-lucide="eye-off" style="width: 16px; height: 16px;"></i> Hide
</button>
```

The button starts `disabled` and is only enabled once a photo loads and `dataset.photoId` is populated. After each photo load (in the fetch response handler), enable the button:
```javascript
document.getElementById('hideBtn').disabled = false;
```

CSS for `.hide-button`:
- Position: fixed, top: 2rem, right: 2rem (mirror position of #controls which is bottom-right)
- Same neumorphic styling as existing buttons but with a subtle red/warm tint to signal destructive action (use #B8867B color like the logout button in settings)
- opacity: 0 / pointer-events: none by default
- Add `.visible` class that sets opacity: 1 / pointer-events: auto (same pattern as #controls)
- When disabled: opacity 0.5, cursor not-allowed (but only visible when `.visible` is also set)
- Transition: opacity 0.3s

Update `showControls()` and `hideControls()` to also toggle the hide button's `.visible` class.

**hideCurrentPhoto() function:**
1. Determine which img is currently active (has `.active` class)
2. Read `dataset.photoId` from that img
3. **If no photoId, return early (guard against undefined/empty -- do NOT POST to hide/undefined)**
4. Immediately call `POST /api/photo/hide/${photoId}` (fire-and-forget for responsiveness)
5. Show toast "Photo hidden" with an Undo button (see toast section below)
6. After a brief beat (~500ms), advance to next photo by calling the existing `nextPhoto()` or equivalent function
7. Hide the controls (call `hideControls()`)

**Toast with Undo:**
Add a toast element (separate from any existing toast) positioned at the bottom-center of the screen. Structure:
```html
<div id="hideToast" class="hide-toast">
  <span>Photo hidden</span>
  <button onclick="undoHide()">Undo</button>
</div>
```

CSS for `.hide-toast`:
- Position: fixed, bottom: 6rem (above the controls area), left: 50%, transform: translateX(-50%)
- Dark semi-transparent background (rgba(0,0,0,0.85)), white text
- Border-radius: 12px, padding: 12px 20px
- Display flex with gap between text and undo button
- Undo button: no background, white text, underlined or bold to stand out
- Hidden by default (opacity: 0, pointer-events: none, translateY(20px))
- `.visible` class: opacity 1, pointer-events auto, translateY(0)
- Transition: all 0.3s ease

**showHideToast(photoId) function:**
1. Store the photoId in a variable (`lastHiddenPhotoId`)
2. Show the toast (add `.visible`)
3. Set a 4-second timeout to auto-hide the toast
4. Clear any previous toast timeout (so rapid hides reset the timer)

**undoHide() function:**
1. Read `lastHiddenPhotoId`
2. Call `POST /api/photo/unhide/${lastHiddenPhotoId}`
3. Hide the toast immediately
4. No need to re-show the photo -- it will naturally appear again in rotation

**Important details:**
- The slideshow keeps cycling while the toast is showing (CONTEXT.md says "does NOT pause the slideshow")
- The hide button tap should NOT also trigger the controls toggle (stop event propagation on the button click)
- If dual portrait mode is active, hide the currently active photo (the one the user sees most prominently). Both photos share the same img elements, so dataset.photoId will be on whichever is active.

After photo loads, hide button should be enabled. Tap Hide -- verify toast appears with Undo, photo advances. If photos are in cache, verify the hidden photo doesn't reappear.

  <files>public/settings.html</files>
  <action>
**New section: Hidden Photos**
Add a new settings-section at the BOTTOM of the page (before the Account section, after the Features section). This section contains:

1. Section title: "Hidden Photos"
2. A count indicator showing how many photos are hidden (fetched on page load)
3. A thumbnail grid of hidden photos
4. An "Unhide All" button
5. Each thumbnail has a per-photo restore (unhide) button overlay

**HTML structure:**
```html
<div class="settings-section" id="hiddenPhotosSection" style="display: none;">
  <div class="section-title">Hidden Photos</div>
  <p class="hidden-photos-description" id="hiddenPhotosDesc">Loading...</p>
  <div class="hidden-photos-grid" id="hiddenPhotosGrid"></div>
  <button class="unhide-all-button" id="unhideAllBtn" onclick="unhideAllPhotos()" style="display: none;">
    <i data-lucide="eye" style="width: 16px; height: 16px;"></i> Unhide All
  </button>
</div>
```

**CSS for the thumbnail grid:**
- `.hidden-photos-grid`: display grid, grid-template-columns: repeat(auto-fill, minmax(100px, 1fr)), gap: 8px, margin: 16px 0
- Each grid item (`.hidden-photo-item`): position relative, aspect-ratio: 1, border-radius: 8px, overflow: hidden
- Thumbnail img: width 100%, height 100%, object-fit: cover
- Restore button overlay (`.restore-btn`): position absolute, top: 4px, right: 4px, small circular button with eye icon, semi-transparent dark background, white icon
- On hover/tap the restore button becomes fully opaque

**CSS for unhide-all button:**
- Same style as existing action buttons but using the warm/coral color scheme (#B8867B) to match logout button aesthetic
- Full width, centered text, includes eye icon

**fetchHiddenPhotos() function:**
1. Call `GET /api/photo/hidden`
2. If response has items (count > 0):
   - Show the section (`#hiddenPhotosSection`)
   - Update description: "N hidden photo(s)"
   - Render thumbnail grid: for each item, create a grid item with `<img src="/api/photo/thumbnail/${item.id}">` and a restore button
   - Show the "Unhide All" button
3. If count is 0:
   - Hide the entire section (no point showing empty state for a rarely-used feature)

**restorePhoto(mediaItemId, gridItemElement) function:**
1. Call `POST /api/photo/unhide/${mediaItemId}`
2. On success: remove the grid item element from DOM with a fade-out
3. Decrement the hidden count in the description
4. If count reaches 0, hide the entire section
5. Show toast "Photo restored"

**unhideAllPhotos() function:**
1. Show confirm dialog: "Unhide all N photos? They'll appear in your slideshow again."
2. If confirmed, call `POST /api/photo/unhide-all`
3. On success: clear the grid, hide the section
4. Show toast "All photos restored"

**Page load:**
Call `fetchHiddenPhotos()` alongside the existing `loadSettings()`, `fetchOnThisDayCount()`, etc. in the initialization block at the bottom of the script.

**Styling notes:**
- Match the existing neumorphic design language (soft shadows, muted colors, Inter font)
- The thumbnail grid should look clean on both desktop and iPad
- Use the existing `showToast()` function already in settings.html for feedback
