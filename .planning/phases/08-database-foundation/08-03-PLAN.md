   - Use a transaction for the bulk update.
   - Update `cache.lastRefresh` and `cache.lastApiCall` in memory (runtime-only).
   - Remove the `saveCache()` call (DB write happens inline).

  <action>
Replace session-file-store with better-sqlite3-session-store:

1. Install better-sqlite3-session-store and uninstall session-file-store:
   ```bash
   npm install better-sqlite3-session-store
   npm uninstall session-file-store
   ```

2. In server.js:
   - Remove: `const FileStore = require('session-file-store')(session);`
   - Add: `const db = require('./db/database');`
   - Add: `const SqliteStore = require('better-sqlite3-session-store')(session);`
   - Replace the session middleware store config:
     ```javascript
     store: new SqliteStore({
       client: db,
       expired: {
         clear: true,
         intervalMs: 900000  // Clean expired sessions every 15 min
       }
     }),
     ```
   - Keep all other session options (secret, resave, saveUninitialized, cookie) exactly as-is.
   - Update the startup log from `Session store: file (./sessions, ttl=1 year)` to `Session store: SQLite (data/okno.db)`.

3. If better-sqlite3-session-store fails to install or has issues (the research notes it's v0.1.0 and possibly stale), fall back to the hand-rolled store from the research (~30 lines):
   ```javascript
   class SqliteSessionStore extends session.Store {
     constructor(db) {
       super();
       this.db = db;
       db.exec(`CREATE TABLE IF NOT EXISTS sessions (
         sid TEXT PRIMARY KEY,
         sess TEXT NOT NULL,
         expired INTEGER NOT NULL
       )`);
     }
     get(sid, cb) {
       const row = this.db.prepare('SELECT sess FROM sessions WHERE sid = ? AND expired > ?')
         .get(sid, Date.now());
       cb(null, row ? JSON.parse(row.sess) : null);
     }
     set(sid, sess, cb) {
       const maxAge = sess.cookie?.maxAge || 86400000;
       this.db.prepare('REPLACE INTO sessions (sid, sess, expired) VALUES (?, ?, ?)')
         .run(sid, JSON.stringify(sess), Date.now() + maxAge);
       cb(null);
     }
     destroy(sid, cb) {
       this.db.prepare('DELETE FROM sessions WHERE sid = ?').run(sid);
       cb(null);
     }
   }
   ```

4. Remove the `fs.existsSync('./sessions')` / `fs.mkdirSync('./sessions')` pattern if it exists in server.js (it doesn't in the current code, but session-file-store may have created a ./sessions directory -- don't worry about cleaning it up, just stop using it).

5. Do NOT include session table creation in db/migrate.js -- let the session store package manage its own table (Pitfall 8 from research). If using hand-rolled store, the CREATE TABLE IF NOT EXISTS runs in the constructor.

IMPORTANT: Verify the session store works by checking the server starts without errors. Sessions are critical -- if the store is broken, OAuth flow breaks. Test by loading the app URL and checking that a session cookie is set.
