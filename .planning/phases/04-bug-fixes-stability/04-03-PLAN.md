Two changes to sw.js, both in the same file:

**Change 1: Guard photo caching with response.ok (BUGFIX-05)**

In the fetch event handler, the photo API section (currently around line 43-57) caches ALL responses including errors. Add a `response.ok` check before caching:

Current code (BROKEN -- caches 502s):
```javascript
if (url.pathname.startsWith('/api/photo')) {
  event.respondWith(
    fetch(event.request)
      .then((response) => {
        const responseClone = response.clone();
        caches.open(PHOTO_CACHE).then((cache) => {
          cache.put(event.request, responseClone);
        });
        return response;
      })
```

Fixed code:
```javascript
if (url.pathname.startsWith('/api/photo')) {
  event.respondWith(
    fetch(event.request)
      .then((response) => {
        // Only cache successful responses -- never cache 502s or other errors
        if (response.ok) {
          const responseClone = response.clone();
          caches.open(PHOTO_CACHE).then((cache) => {
            cache.put(event.request, responseClone);
          });
        }
        return response;
      })
```

The `.catch()` fallback to cache remains unchanged -- that's for when the network is completely unavailable, which is correct behavior.

**Change 2: Bump CACHE_VERSION to okno-v1.1 (DEPLOY-01)**

Change line 1:
```javascript
const CACHE_VERSION = 'okno-v1.1';
```

Also update the PHOTO_CACHE constant to match:
```javascript
const PHOTO_CACHE = 'okno-photos-v1.1';
```

This triggers the following cascade on the iPad PWA:
1. Browser detects byte change in sw.js, downloads new SW

4. New SW pre-caches all STATIC_ASSETS with bug-fixed HTML
5. `clients.claim()` takes control of the page

CRITICAL: This plan depends on Plans 01 and 02 being complete. The sw.js cache version bump must be the LAST change because it triggers re-caching of all static assets. If sw.js is updated before slideshow.html and index.html are fixed, the iPad will re-cache the old buggy files.
